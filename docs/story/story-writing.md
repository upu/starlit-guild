# 物語・会話の制作指針

ゲーム本体に表示しない、書き手向けの資料。[キャラクター設定](../characters/README.md) と併せて使う。物語の文章は `lib/stories.ts` に実装し、この資料そのものをアプリへ取り込まない。

## 制作資料の読み分け

| 資料 | 確認する内容 |
| --- | --- |
| [世界観と物語](world-and-story.md) | 合意した物語の核、二つの村と交易先の街、塔と苔の共通ルール、制作案と将来の種 |
| [第一章プロット](story-part-1.md) | 公開済み第一章の出来事、交易から塔の復旧までの因果、後へ残る事実 |
| [キャラクター設定](../characters/README.md) | 人物の判断、口調、関係性、既存の加入理由 |
| [関係性と掛け合い](../relationships/README.md) | 複数人にまたがる設定。アリアとレオンは [専用資料](../relationships/aria-leon.md) を読む |
| [マッドハロウィン](../factions/mad-halloween.md) | メリルとプティの所属組織、敵役・来客としての扱い |
| 本書 | 各場面の文章化、表示条件、読み返しの扱い |

公開済み第一章は「村の交易の仕事 → 街で塔の話 → ついでの見物 → 便利な苔灯を持ち帰る → 弱まった姿への見覚え → 再訪・比較・調査 → 地域の人との復旧 → 普段の道の回復」と進む。塔ごとに原因と解決を変え、竜討伐や世界救済の使命へ戻さない。第一章の冒険は二人だけで進み、他の既存キャラは登場しない。第二章以後の出来事は、各章の計画で公開済みの事実と制作案を分ける。

苔は初めに便利な発見として描く。「灯りを食べるもの」のような章題や「灯吸い苔」というアイテム名で原因を先に明かさない。暗くなった姿から森の苔との似かよりに気づき、比較と再訪を通じて性質を確かめる。書き手だけが知る因果を、序盤の地の文へ混ぜない。

第一章の結末は、近隣の塔の灯りと暮らしの回復を喜んで完結する。他の土地の相談や新たな事件の予告を足さない。第二章の導入は第二章側で描く。設定資料の人工栽培などの将来案を、第二章の確定事項や第一章末尾の伏線として扱わない。人工栽培問題を採用するなら、第一章の発見が噂として他の街に伝わった後に発生する順序を守る。

## 制作担当への委任

人物の個性や関係性、加入の物語は制作担当が考えて決め、実装と資料へ反映する。ユーザーに細かなストーリー案の合意を繰り返し求めない。制作の核を守り、人物の言葉や行動がつながるように自分で判断する。

既存の加入理由・加入順・クエスト順だけに新しい物語を従わせない。制作の核を土台に必要な設定を具体化し、台詞・進行・担当資料を揃える。[第二章計画](story-part-2.md) ではミラを最初の新しい仲間とし、その先の加入順は未定。

## 第二章では人物のとがりを保つ

第二章の目的を人格的成長や欠点の克服にしない。能力が育つことと、人物が無難になることを分ける。小さな反省や助け合いがあっても、ミラの過剰な献身、アリアの早合点や方向音痴、レオンの過剰な備え、プティのいたずらが一章で治ったことにはしない。

同行するほど「この人はここまでやるのか」と分かり、今後もトラブルの元でいられる場面を作る。人物ごとの具体的な癖は [ミラ](../characters/mira.md)、[アリア](../characters/aria.md)、[レオン](../characters/leon.md)、[プティ](../characters/pumpety.md) を正とする。アリアの迷子による離脱・意外な場所での復帰は将来案であり、今回は使わない。

第一章の約束や親しさは引き継ぐ。第二章の加入や世界観の伏線のために、完結した第一章の終幕へ予告を追加しない。

### 第二章の口癖の反復

第二章では人物に設定した口癖・構文を積極的に繰り返し、普段の掛け合いで覚えてもらう。山場では定番の言葉を効かせたり、少し形を変えたりする。毎回別の言い方へ薄めず、同時に全ての台詞へ機械的に挿入しない。単語の一覧だけでなく、その人が何を引き受けるか・何を隠すかに結びつける。

台詞の型の正本は [アリア](../characters/aria.md#口癖台詞の型)、[レオン](../characters/leon.md#口癖台詞の型)、[ミラ](../characters/mira.md#口癖決め台詞構文)、[プティ](../characters/pumpety.md) に置く。具体的な使い方は [第二章計画](story-part-2.md) の会話案を参照する。

プティの名前は一人称から漏れるが、主人公たちはこの時点で名前呼びせず「あなたも」などと呼びかける。自己紹介や従来記録の初遭遇を流用しない。パンプキンヘッド姿では、顔の表情を地の文や画像で先に見せない。

## 目指す体験

仲間の「この人ならこう言いそう」が分かり、ときどき意外な一面に出会う。依頼での出来事が拠点の日常に残り、「一緒に過ごした」と感じられるようにする。

人物紹介では普段の癖や外から分かる特徴を伝える。内面の気持ちは、選ぶ行動、差し出すもの、返事までの間で見せる。全員に重い過去や大きな秘密を持たせる必要はない。

## アリアとレオンの温度

レオンはアリアを名前で呼び、「お前」は使わない。ほかの仲間にも名前か自然な主語の省略を使う。親しさを乱暴な呼びかけで表さない。

制作の核にするユーザーの好みは、「幼なじみで、お互い好意があるけど、煮え切らない二人を見るのが好き」。これを優先する。

相互の好意は書き手が共有する設定に留める。ゲーム内に「幼なじみの、まだ言えない気持ち」「幼なじみへの気持ち」のような解説や、関係性の答えを示すハートを添えない。プレイヤーが、席を選ぶ、相手の分も用意する、手を止めるといったしぐさから「そうなのかもしれない」と察する余白を残す。地の文も気持ちを断定せず、その場で見える動作を描く。

距離が近づいても、すぐに告白や交際へ進めない。毎回第三者が割り込んで告白を妨害するのではなく、本人たちの言葉の選び方や照れで、少し言い残す。その代わり、ひとつ小さな変化を残す。

| その場のきっかけ | 表向きの理由 | 読み手に伝わる気持ち | 残る変化 |
| --- | --- | --- | --- |
| 崖道で手を取る | 滑らないように | 危険が去っても離したくない | 帰ってから、いつもより近くに座る |
| 好物のパンを取っておく | 好みを知っているから | 自分の分より先に相手を考えた | 次は自分が相手の好物を選ぶ約束をする |
| 休憩を提案する | 自分が休みたいから | 相手に無理をさせたくない | 素直に隣で休める |
| 依頼のない日に誘う | 少し歩きたいから | 用事がなくても一緒にいたい | ふたりだけの予定ができる |

これは毎回同じ構造にするための台本ではなく、感情と行動を結びつける例。アリアから支える場面や、レオンから誘う場面も作る。

### 避けたい描き方

- 関係が毎回初期状態へ戻り、以前の約束や優しさがなかったことになる。
- アリアが常に迷惑をかけ、レオンが一方的に尻拭いする。
- レオンの気遣いが、束縛や行動の禁止になる。
- 嫉妬や第三者の恋敵で、ふたりの信頼を安易に壊す。
- 仲間全員が常にからかい、ふたりの本音を大声で代弁する。
- 地の文が、すべての台詞のあとに「本当は好きだから」と解説する。
- どの場面でも三点リーダーを使い、全員が同じ照れ方をする。

ミラが黙ってふたつのカップを置くくらいの、見守る余白を残す。

### スチル

ゲーム内の画像一覧は「アルバム」と呼ぶ。「思い出」には会話をステージ順に出発前→達成後で並べ、画像はアルバムを開くまで表示しない。シナリオの会話は一発言・地の文一行ずつ送り、画像は対応する動作の行から表示する。「スチル」は制作資料内で使う用語とする。

節目の場面には一枚絵を添える。立ち絵の髪・目・衣装を引き継ぎ、視線、手の位置、座る距離、小道具で描く。絵にも恋愛を断定する文字やハートを入れない。全場面を同じ密度で飾らず、出来事が記憶に残る場面を選ぶ。

表示先と出現位置は `lib/story-art.ts`、画像は `public/stories/` に置く。物語がその動作に到達したページから表示し、先の出来事を冒頭で見せない。通常の読了条件と「旅の思い出」を使い、追加の資材消費やランダム抽選を設けない。縦横比を保って画像全体を表示する。生成プロンプトと採用した場面は [スチル制作記録](../art/story-art.md) に残す。

## 台本の表記

書式がぶれると、同じ画面の中で読み方の作法が変わってしまう。実装時は次を守る。

| 対象 | 書き方 | 文末の句点 |
| --- | --- | --- |
| 主役と仲間（`a()` / `l()` / `m()`） | 話者を分けた台詞行 | **付ける** |
| 名前のある相手で、同じ場面に複数回出る人（`s()` ヘルパー） | 地の文の中に `名前「…」` | **付けない** |
| 姿や正体を伏せている相手（`v()` / `p()` ヘルパー） | 地の文の中に `木々の奥からの声「…」` など | **付けない** |
| その場限りの一言 | 地の文へ `「…」` で埋め込む | **付けない** |

鉤括弧の中は文末の句点を置かない。話者を分けた台詞行には置く。名前のある相手を毎回ラベルにすると主役と同格に見えるので、一度きりの発言は地の文へ埋め、繰り返し会話へ加わる相手だけラベルにする。

感嘆符・疑問符のあとに続きがある場合は**全角スペース**で空ける。半角と混ぜない。

## 場面ごとの役目

### 出発のひと幕

依頼の具体物をひとつ出し、それに対する人物の反応を描く。世界設定の長い説明より、「なぜこの依頼がふたりの記憶になるか」を置く。短い数往復を基本にする。

### 道中の掛け合い

通常は2〜3台詞で、寄り道、景色、疲れ、助け合いに反応する。状況と人物の組み合わせに合った話にする。特定の過去の場面を前提にする場合は、その出来事を経験した条件も考える。

### 達成後のひと幕

出発や道中の小道具を持ち帰り、相手への理解や次の約束へつなぐ。報酬の説明だけで終わらせない。語りの「冒険のあとで」は回想として読めるようにし、自動周回中の現在位置と混同させない。

### 拠点の日常

食事、修繕、片付け、休憩など、生活の行動を軸にする。戦闘用の決め台詞の使い回しを避ける。登場人物がその場にいる条件を設け、特定の人物が不在なら別の会話を選ぶ。

### 絆で変わる会話

最初からある親しさを土台に、頼み方や返事、物理的な距離が変わる。幼なじみなので、低い絆を「初対面の遠慮」として描かない。高い絆でも、恋愛の言葉には踏み切れない余地を残す。

## 新しい話を作るメモ

実装前に次を短く決める。すべての候補を先にゲームデータへ登録する必要はない。

| 項目 | 記録すること |
| --- | --- |
| 状態 | 人物を深める軸／採用済み |
| 登場人物と場所 | 誰が実際にそこにいるか |
| きっかけ | その場で何が起きたか |
| 人物の望み | 相手に何をしてほしい、何を伝えたいか |
| 言えること・言えないこと | 表に出す台詞と、書き手だけが知る気持ち |
| 小さな変化 | 会話後に何が一歩変わるか |
| 前提 | 必要な仲間、依頼、設備、絆、過去の場面 |
| 設定への影響 | 新しく確定する好み・過去・関係性 |

一度に全員の物語を恋愛へ寄せない。ミラとフィン、ガルとミラ、ルナとノエルなどは、それぞれに合う信頼や親しさを掘り下げる。

## 実装と資料の境界

- この資料はGitで管理する制作資料。ゲームへの取り込み、画面への自動表示、設定全文を返すAPIは作らない。
- ゲームに表示するプロフィールや台詞は、場面に必要な分だけ別途実装する。資料の「人物を深める軸」を公開済みの設定として紹介しない。
- シーンIDは保存記録から参照されるので、公開後の改名・削除には互換性の扱いが必要。台詞の修正とIDの変更を混同しない。
- 初回出発、途中帰還、留守中の達成、読み飛ばし、読み返しを考慮する。物語を読む操作を周回の必須条件にしない。
- 既存の記録に対する解放方針は [README](../../README.md) と実装を確認する。編成の記録がない旧データについて、実際にふたりが参加したと断定しない。

## 編集時の確認

1. [キャラクター一覧](../characters/README.md) から登場人物の個別ファイルを開き、制作の核と採用済み設定を読む。リンク先の関係性・所属組織も確認する。
   塔や本筋の話では [世界観と物語](world-and-story.md) と [第一章プロット](story-part-1.md) も読み、制作の核・制作案・公開済みの区分を照合する。
2. 個別ファイルが案内する既存シーンを [物語データ](../../lib/stories.ts) で確認する。加入・マッドハロウィン・来客の会話は削除済みのため、参照するときは資料側の記録を使う。
3. 話し方と判断がその人物らしいか、相手が違っても同じ台詞になっていないかを読む。
4. 前提となる人物・場所・過去の出来事と、表示条件を照合する。
5. 新しい事実を採用したら、個人・関係性・組織の担当する資料を更新し、根拠のシーンIDと関連リンクを記録する。候補のままの事項は人物を深める軸として残す。同じ共通設定を複数のファイルへ全文コピーしない。

資料だけの変更ではゲームのビルドやテストを増やさず、リンク・根拠・設定の区分を確認する。実装を変更したときは、変更に関係する保存と進行の検証を行う。

## 放置ゲームでの出会い

従来記録の実装は「出会い → 資材・希少素材の準備 → 専用クエスト → 加入」だった（削除済み。記録は [加入設計](../archive/recruitment.md)）。費用は人物の購入価格ではなく、困りごとを解決する支度として扱っていた。この順序は新しい物語の固定条件ではない。第一章に加入はなく、第二章ではミラを迎える。具体的な進行条件と、その先の仲間の出会い方・順序は各章の実装時に決める。

準備の途中にも新しい話を残す。希少素材が半分集まると、その人物の強がりや弱みを知る短い話が開く。読まないと素材集めが進まない条件は設けない。留守中に条件を満たした話も後から読める。加入の最後には、助けられた人物自身の選択を描く。

長い準備期間を、確率だけで先の見えない待ち時間にしない。集め先・次の1個までの進捗・使う理由を見せる。後半の期間は初期バランスとして計測し、実際の遊び方に合わせて調整する。

## 仲間と来客の会話

`lib/character-encounters.ts` の4話は「思い出 → 仲間と来客」で読む。必要な仲間の加入と設備、敵役が来る話では対応する通常クエストの達成を条件とする。初遭遇の物語の読了は強制しない。加入・達成は既存セーブから判定し、追加の資材や保存形式は設けない。

拠点で会話を薦めるときは、話に参加する仲間が実際に拠点にいることを確かめる。チャチャとミラだけの話に、アリアとレオンの在席は要求しない。メリルとプティは来客であり、加入済みの仲間として扱わない。解放済みの思い出は参加者が冒険中でも読み返せる。
