# キャラクター設定の入口

案内：[資料案内](../README.md)

ゲーム内の台詞や出来事を作るための制作資料。プレイヤーに見せる人物紹介ではなく、書き手が人物の判断や言葉を揃えるために使う。アプリから読み込まず、`public/` にも配置しない。

会話を追加するときは [物語・会話の制作指針](../story/story-writing.md) も参照する。

世界・塔・苔と旅の動機は [世界観と物語](../story/world-and-story.md)、公開済み第一章の塔の事件は [第一章プロット](../story/story-part-1.md)、第二章の計画は [第二章計画](../story/story-part-2.md)、その実装状況は [第二章のゲーム実装](../gameplay/chapter-two-gameplay.md#実装状況) を参照する。第三章の計画は [第三章計画](../story/story-part-3.md) にあり、実装状況は[第三章の実装仕様](../gameplay/chapter-three-gameplay.md#実装状況)を参照する。

## 読み始める順序

[世界観](../story/world-and-story.md) と [執筆指針](../story/story-writing.md) を確認し、下の一覧から登場人物のファイルを読む。個別ファイルにある関係性・組織・対象プロット・既存シーンへのリンクもたどる。キャラ全員や画像生成記録の全文を毎回読む必要はない。

人物の設定は `docs/characters/<キャラID>.md`、複数人の関係は `docs/relationships/`、組織は `docs/factions/` を正本とする。世界の共通ルールは世界観資料、文章の書き方は執筆指針、現行の数値・表示条件は実装を確認する。重複した全文を各ファイルへコピーせず、担当する資料へリンクする。

## 制作の進め方

ユーザーは、人物設定・物語・関係性を制作担当が主体的に考え、資料とゲームへ反映することを希望している。細かな設定案ごとに合意を求めたり、承認待ちとして制作を止めたりしない。既存の人物らしさと幼なじみふたりの温度を保ちながら、必要な設定を決め、台詞と出来事にする。

実装されている事実と、今後描いていく人物の軸は区別する。この区分は整合性のために使い、設定を作るための承認手順にはしない。制作資料そのものはゲームに読み込ませない。

既存の口調・関係性・加入理由は参照できる素材だが、新しい物語を従来記録の加入順へ無理に合わせない。第一章はアリアとレオンだけで完結した。[第二章計画](../story/story-part-2.md) ではミラを最初の新しい仲間、プティを山道の敵役とする。[第三章計画](../story/story-part-3.md) ではフィンを迎える。その後の加入順は未定。第二章以後は人格的な成長や欠点の克服を目標にせず、とがった性格と繰り返すトラブルを保つ。

## 設定の扱い

| 区分 | 意味 |
| --- | --- |
| 制作の核 | 人物・関係性の継続した方向。制作担当がこれを土台に具体化する |
| 採用済み | 現在の作業ツリーのプロフィールや物語に登場する設定。今後も維持する義務や、公開状況を意味しない |
| 人物を深める軸 | 今後の場面作りの方向。場面を作る担当が具体化して採用する。承認待ちの項目ではない |
| 制作案 | 新しい物語の土台として具体化した設定。制作の核と区別し、公開済みとは扱わない |
| 未設定 | 今のところ決めていない事項。必要な場面を作る際に検討する |

人物を深める軸を採用したら、この資料の区分と根拠となる場面を一緒に更新する。資料に記載しただけでゲームへ自動追加することはない。

## オリジナルキャラクターとマッドハロウィン

ユーザーのオリジナルキャラクターを追加。外見は提供された参考絵、種族・性格・武器は今回指定された設定を核とする。参考絵に別の武器があっても、メリルはガントレット自体に弦が張られた琴、パンプティは人形、チャチャは大剣を使う。

個別の外見・口調・武器は各人物ファイル、組織の共通設定は [マッドハロウィン](../factions/mad-halloween.md)、画像の制作記録は [オリジナルキャラクター画像](../art/original-character-art.md) を参照する。元の参考絵のファイル名は識別情報であり、リポジトリ内に元画像があるとは限らない。参照画像を取得できない場合は、その制約を明示する。

## 共通の未設定事項

個別の人物資料で確定していない年齢、村と街の固有名、家族の職業、過去の事件、加入後の詳しい生活史。ミラ・フィン・リコの年齢はそれぞれの人物資料を正とする。アリアはエルフ、レオンは人間という種族案と成長の速さは [世界観と物語](../story/world-and-story.md) の制作案に従う。幼い頃に塔へ行く約束は設定していない。空欄を埋めるためだけに悲劇や秘密を追加しない。

## 塔の物語で人物を動かす軸

第一章では、アリアとレオンが塔への訪問、苔の発見、比較、原因調査、水路修理、苔の撤去、再点灯まで進めた。他の仲間は登場しない。素材の性質と各人物の利害は [苔の設定](../story/world-and-story.md) を正とし、他の人物が苔に関わる内容は第二章以後の制作案として扱う。

- アリアは草木・風・匂い、レオンは道・足場・通行する人の様子に目を向ける。ふたりの観察と住民の知識を組み合わせて原因に近づく。特別な血筋の能力で即座に解かない。
- リコは発光と毒の研究のため、苔を増やして自分で確かめる。第四章の制作案では、塔のそばで苔を増やし、被害まで考えが及ばなかった張本人とする。被害を知った後は後始末に取りかかり、利益のために住民の被害を承知で放置する業者とは判断を分ける。詳しくは [リコ](lico.md#第四章での役割制作案)。
- ルナは既に得られた観察から仕組みを調べる。ミラは往診など暮らしへの用途を考え、復旧を優先する。二人をリコと同じ「研究のために増やして確かめる人」にしない。
- メリルは珍しいものの噂を聞いて、食べられるか確かめに来る。標本や比較用の苔にも食欲を向ける。食の感想が偶然手がかりになっても、献身的な調査員や全てを解く味覚の持ち主にはしない。
- 利益優先の業者とマッドハロウィンの関係は今後検討する。自動的に同一組織と扱わない。加入理由や加入順も、第二章以後の物語に合わせて見直せる。

## 仲間になるまでの物語

従来記録の加入条件・進行は [仲間との出会い](../archive/recruitment.md) に記録する。以下は削除した従来記録の実装の記録で、新しいシナリオの加入理由・順序を拘束しない。

各人の事情・準備中の一面・加入理由は個別ファイルの「現行の加入エピソード」に置く：[ミラ](mira.md#現行の加入エピソード)、[ガル](garr.md#現行の加入エピソード)、[ルナ](luna.md#現行の加入エピソード)、[旧ポピー](lico.md#旧設定ポピーの記録)、[ノエル](noel.md#現行の加入エピソード)。

従来記録ではミラ → フィン → ガル → ルナ → ポピー（現在は[リコ](lico.md)へ置き換え） → ノエルの順に出会いがつながっていた（実装は削除済み）。第一章に加入はなく、第二章ではミラ、第三章ではフィンを迎える。フィンが同行を続ける理由は[人物資料](finn.md#同行を続ける理由)を参照。[第四章計画](../story/story-part-4.md) ではリコを迎える案とする。その先の順序は未定。新しい章を実装するときは、その章で決めた出来事と人物の登場条件を揃える。

## 根拠と実装の参照先

- [基本プロフィールと既存ペア](../../lib/roster.ts)：`heroes` / `bonds`。現在のゲームが参照する人物データで、アリア・レオン・ミラの3人だけを持つ。
- [現在の物語・掛け合い](../../lib/stories.ts)：`stories` / `characterNotes` / `journeyBanter` / `coupleCombo`。
- [現在のゲーム](../../lib/game.ts)：特技、絆、戦闘の数値。ここを参照し、人物設定資料へ複製しない。

- [追加キャラクター](../../lib/original-characters.ts)：メリルとプティのプロフィール。チャチャのデータは削除済みで、設定は [chacha.md](chacha.md) が正本。
- 仲間と来客の会話、マッドハロウィンの物語、加入の物語、拠点の暮らし、旧クエスト9件と旧仲間5人のデータは削除済み。内容は各資料の記録で確認する。

## 追加・更新するとき

新しい人物は [_template.md](_template.md) を使い、キャラIDをファイル名にする。未設定の項目は無理に埋めない。既存人物には必要な見出しを追加し、採用済みの出来事と制作案を同じ箇条書きへ混ぜない。台詞例を新しく作る場合は、実装済みの引用か制作例かを明示する。

個人の設定変更は個人ファイル、関係性の変更は関係性資料、組織の変更は組織資料を更新する。関連する人物からリンクし、実装した場合は根拠のシーンIDとファイルを記録する。人数や組織を増やしたら、この一覧と [ドキュメント案内](../README.md) の導線を確認する。

旧 [characters.md](../characters.md) は既存リンク向けの案内だけに使い、設定本文は追加しない。
