# 横スクロール戦闘の試作

本編への採用を判断するための独立した試作。タイトル画面の「横スクロール戦闘を試す」、または `/battle-prototype` から開く。本編の章・ステージには対応づけない。

## 遊び方

- 人物が個別の速度と射程で森の出口まで自動で進む。アリアは弓、レオンは剣で攻撃し、ミラのいる編成では自動回復も行う。攻撃・被弾には向きに応じたノックバックがあり、後方の敵には振り返って対応する。HPはキャラごとに持ち、戦場の人物下にバーを表示する。画面外の重複HP欄は置かない。
- 画面上の「試すステージ」で比較できる。変更すると試作の進行だけをリセットする。道中に必須の選択は出さない。
  - ふたりの森：敵は一度に最大2体、採取2か所。密度を抑えた導入用。
  - 三人の街道：ミラを含む3人、敵は一度に最大4体、採取2か所。2体制限は共通ルールではない。
  - 薬草の群生地：3人で長めの採取を3か所。各地点で作業の進行に応じて前後から計2回の襲撃を受ける。
  - 荷車の配達：包み直し・荷札確認 → 荷車で運搬 → 荷下ろし。荷車は仲間と一緒に移動し、襲撃中と護衛の帰り待ちは停止する。荷物へダメージを与える戦闘として扱わず、作業の進み具合を表示する。
  - プティとふたりの役者：小さな人形と運搬用ゴーレムを止めるボス戦。後方の覆面姿のプティが追撃を指示する。人形2体が止まるとプティも撤退し、討伐数には加えない。第二章の既存構成・外見を参照した独立試作で、本編の進行とは連動しない。
- 敵がいない採取地点では到着した全員が作業する。敵が出るとレオンが護衛へ移り、ほかの人物が採取を続ける。敵を倒したら護衛も採取に戻る。ミラは採取中でも傷ついた仲間を回復する。レオンが倒れた場合は生存者が護衛を引き継ぐ。
- 採取完了ごとに試作内の薬草が3個増え、HPが少し回復する。育成や報酬選択は発生しない。
- 荷物の作業は全員で自動進行する。包み直し・荷下ろしはタップで早まり、運搬中のタップは敵への援護になる。荷車の瞬間移動や襲撃の飛ばしには使えない。完了時は薬草ではなく配達回数が増える。
- 戦場または「タップで援護」を押すと追加攻撃。採取地点での手助けは作業を早める。「技の付け替え」で複数対象攻撃・速射・防御を変更できる。付け替えではHP・距離・攻撃待ち時間をリセットしない。
- 各地点の戦闘・採取を終えて出口まで到達すると6秒休んで自動周回。森と街道では最後に大きなスライムが待つ。全滅時も6秒休んで復帰する。休憩中の手助けは復帰を早める。
- 道中の強化取得、進路選択、報酬選択はない。会話の読了も進行条件にしない。
- 掛け合いは既存の `idleBanter` を編成に合わせて使用し、30秒ごとの会話を1行ずつ表示する。過去の会話をスクロールしている間は下端へ引き戻さない。

## 本編との境界

試作専用の固定能力・敵・技を使い、本編の育成・装備計算・経験値・物語・セーブ・クラウド保存を読み書きしない。画面を閉じると試作の進行はリセットする。「やり直す」は試作内の進行だけを戻し、選んだ技は保つ。

本編の第一章・第二章の到達戦力、追加育成時間、第三章の開始条件は変更しない。試作の短い踏破時間を本編の章目標へ流用しない。正式導入時には保存・報酬・採取／運搬・章の難易度・留守中精算との統合を別途設計し、[章ごとの基準](progression-balance.md)に沿って測定する。

## 実装と検証

- `lib/scrolling-battle.ts` が射程・HP・自動行動を50ms刻みで処理。`scrolling-travel.ts` が個別移動・共同採取・護衛、`scrolling-stages.ts` がステージ構成を担当する。
- 描画は `scrolling-presentation.ts` で直前と現在の位置を補間する。20Hzの位置更新をそのまま描画していた段付き移動を解消する。描画から戦闘時間を進めず、背景のサイズ変更と草の描き直しはリサイズ時に限定する。PC性能の限界を断定する計測結果はない。
- 開いたタブのタイマー遅延は最大12時間までまとめて精算する。一時停止・素材読み込み中・描画エラー中はシミュレーションを止める。ページを閉じた後の進行は保存しない。
- `app/battle-prototype/` がPhaser描画とReactの操作・チャットを担当。小さい画面はページ内を縦スクロールできる。「動きを減らす」では背景の移動、歩行のコマ切り替え、攻撃エフェクトを省く。
- 小表示用に顔・輪郭・特徴的な装備を整理した3人の画像と採取動作を新規生成し、`public/animations/road/` に保存。矢・剣撃・回復・採取も画像エフェクトを使用する。既存本編の画像は維持する。組み込みimage_genの最終プロンプト・参照・原本は [生成記録](art-generation/scrolling-prototype-art.json)。原本の画素を加工せず、Phaserの矩形と足元アンカーで武器のはみ出しを含むコマを読む。
- 歩行は専用の4コマ画像へ交換し、脚を上げる左右の中間姿勢を追加。各コマの足元と人物の高さを揃えて再生する。薬草は細かな輝きや飾りを省いた新しい画像、荷車とボス3体も透過画像を使用。[追加素材の生成記録](art-generation/scrolling-prototype-refinements.json)に原本・採用先・最終プロンプトを保存する。
- `node --test tests/scrolling-battle.test.mjs`：全技構成での無操作踏破と周回、時間精算の一致、手助けの効果、全滅からの復帰、技変更・チャットの独立性。
- ローカル開発サーバー起動後 `node tests/scrolling-battle.browser.mjs`：独立したChromiumコンテキストで画面幅、Phaser起動、付け替え、一時停止・再開、周回、チャット、端末保存の非変更を検証。必要なら `PLAYWRIGHT_MODULE` / `CHROME_PATH` を指定。画像と結果は `work/scrolling-battle-browser/` に出力。

ブラウザー幅の確認と実際のスマホでの操作・体感は別。試作への感想を確認してから本編への適用範囲を決める。

2026-09-20の無操作シミュレーション（標準の技）：ふたりの森59.5秒／6体／薬草6個、三人の街道62.65秒／12体／薬草6個、群生地80.1秒／12体／薬草9個。全て初回踏破・全滅0回。人の操作による実測ではない。

追加2ステージの同条件：荷車の配達58.2秒／4体／配達1回、プティ戦43.8秒／人形2体。全技構成で無操作周回・全滅0回、時間精算の一致を検証。ブラウザーでは5種類の切り替え・踏破、画像の読み込みと再試行を確認する。
