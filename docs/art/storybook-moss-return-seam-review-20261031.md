# 1-9・冒険から帰還会話への接続と縦長画面（2026-10-31）

## 冒険の片付けを繰り返さない接続

用語集の1-9 `tower-moss-removal` / `tower-moss-removal-return` と第一章台本の冒頭を照合した。冒険側は最後の籠の運搬、灯りでの点検、灯りの返却、二つ目の蓋の閉鎖まで実行してから完了カードを出す。このあと会話の冒頭でも同じ閉鎖を再生していたため、実プレイで片付けを見終えた場合は塔の表へ歩いて戻る場面につなぐ。

`restorationHandoffState.completed` は実際に観測した冒険のスナップショット・同じ実行の描画完了・未スキップを確認する。保存データの達成済みだけでは成立しない。`PhoneFrame` → `QuestCompletion` → `StoryReader` の一時的な `completedAdventure` として渡し、最初の表示だけ `lib/storybook/adventure-entry.ts` で差し替える。再読・再読み込み後の会話や描画スキップでは従来の閉鎖も再生する。セーブ項目、本文、表情、クエストの工程・報酬・時計は変えない。地図帳の裏手の排水路から塔の表へ戻る関係も維持し、新しい地理設定は追加しない。

到着時は管理人を先頭に同じ歩速で入る。座石を踏まないよう手前の通路（bottom 6）を通り、二人は次の台詞の位置、管理人は階段の脇へ向かう。アリアは木べらを持った歩行を続ける。地面の道具はx24/bottom28へ避け、座る時の道具の置き下ろしの接点は維持する。動作中のタップは到着後に次の1表示だけへ進む。時計更新で舞台の合図を作り直し、歩行を最初へ戻さないことも検査する。

本編構成を一時データで確認する入口は `/sprite-lab/storybook/moss-removal-phone`。従来の冒険見本からもリンクする。端末セーブは使用しない。

## スマホ幅で見つけた描画順と構図

途中画像を拡大すると、スマホ幅では人物・籠・荷車が背景の裏へ隠れていた。これまで多くの座標検査は3:2の画面を使い、実際の縦長の冒険表示で生じる負のlaneを検査していなかった。`10 + lane * 10` で前後順を決めると、画面内の足元でも背景・陰影より奥になる。緑のHP表示と点検口だけが残るため、進行完了やエラーログだけでは見落とす。

`roadFigureDepth` は固定した作業場（水路・荷造り・道標・防衛・作業場）の人物・敵・荷物も、画面に投影した足元の高さから描画順を決める。水路の通常作業者と作業物も同じ計算へ揃える。地面の点検口の縁・苔・下ろした蓋は `WaterwayProp.layer: "ground"` で背景と人物の間へ置く。持ち上げた蓋は管理人の足元に沿う前後順を使い、地面へ戻してから地面の層へ移す。これにより地面の蓋が人物を覆う別の問題も避ける。

縦長画面では同じ縮尺の作業場を、作業の足元が画面中央より少し下へ来る位置へ移す。人物だけを拡大せず、背景・蓋・荷車・籠・人物の投影を `fixedRoadLayout` で一緒に移す。スマホ幅では舞台の下辺が会話欄のすぐ上へ収まる。地面の相対距離と人物の体格は維持する。

## 実画面で確認した範囲

PC1280×900と390×844 CSS pxで、一時データを使う本編構成の冒険・完了カード・帰還会話を操作した。記録は `work/moss-return-seam-20261031/`。約350ms間隔の画像、表示状態のテキスト、途中画像の一覧を使い、足元、手と籠・灯り・蓋、運搬、作業者との距離、座石と道具の迂回、立位と低い姿勢、名前、台詞の順を目視した。全フレーム動画やスマホ実機の検査ではない。

- 最終ソースのスマホ幅の冒頭から約55秒は `visible-mobile-full`、その後の完了待ちは `visible-mobile-finish`。記録の間には観測間隔があるため、途切れない全工程の動画としては扱わない。
- 最後の点検と閉鎖は帰着直前の工程から30秒間続けて撮り直した。両幅の `visible-{pc,mobile}-final-work` で人物、籠と荷車、灯りの拾い上げ・点検・返却、蓋の運搬・閉鎖、完了カードまで確認した。これは冒頭からの連続記録とは別の確認。
- そのまま完了カードから会話を開き、`visible-{pc,mobile}-from-final-arrival` の約13秒で、閉鎖を繰り返さず表へ戻り、次の台詞の位置へ着くことを確認した。PCの全工程の区間記録 `pc-run-final-a/b/c` は描画順変更前で、最終ソースの全工程の証拠には使わない。
- スマホ幅では `visible-mobile-arrival` → `visible-mobile-speech` → `visible-mobile-return-page-3〜7` で到着、台詞、道具の置き下ろし、着座、管理人の出入りと上向き、一枚絵への切替まで操作した。PCの同じ会話部分は `pc-arrival-final` / `pc-speech-final` / `pc-return-page-3〜7`。その後の修正は冒険側の描画順・縦長配置で、この会話の動作は変えていない。
- 途中タップは `mobile-arrival-before-tap` / `mobile-arrival-after-tap` と状態テキストで確認した。最初の表示を保って歩き終え、2表示目だけへ進む。人物の欠落は冒険側で、これらの会話の人物は表示されていた。
- `mobile-run-final-a/b/c` と `mobile-final-work-continuous` は人物が隠れていた修正前の記録。確認済みの根拠から外す。タイムラインを完了保存できなかった `final-pc-adventure-a` と短い記録試験も根拠には使わない。

実画面で人物の表示を確認した後のエラーログ `visible-mobile-errors.json` / `visible-final-errors.json` は空だった。一枚絵は既存のまま静止している。冒険の点検口と会話の塔前は、片付け後にカメラを切り替える別の構図としてつなぐ。
