# 会話舞台の背景読み込み

- 手描き背景が未準備の間は人物・小物を先に描かず、舞台の準備表示を出す。会話送りも待ち、背景が読み込まれて画像のデコードが終わってから、その台詞の舞台と動きを始める。次に異なる背景を同じ会話の中から探して先読みする。
- 背景取得が失敗した場合や8秒以上応答しない場合は、同じ舞台・人物・小物のまま既存の背景を使い、会話を続行する。先読みが失敗した画像は次の機会に再取得できる。一枚絵の表示やストーリーの保存は変更しない。
- 倉庫背景の応答を遅らせたローカル確認では、準備中の画面に人物が現れず、タップしても1行目から進まなかった。背景を404にした場合と30秒遅らせた場合は、予備背景を表示して会話を進められた。予備背景でも取引先の人が二重表示されないことをPC幅で確認した。
- 通常表示の4-2帰還では、ブラウザーのPC幅と390×844 CSS pxで7行目から夕方の8行目への切り替えを確認した。後から加えたデコード待ちの変更後はPC幅を再確認した。スマートフォン実機は未確認。
- `tests/storybook-stage-images.test.mjs` は次の背景の選択、同一画像の重複取得防止、失敗後の再試行、タイムアウトとデコード完了待ちを検査する。84会話1788表示について現在と次の背景を計算し、参照画像の欠落がないことを確認した。関連42テスト、型検査、対象lintも成功。人物や小物の画像の先読み、全場面の接点・動作の通し確認は別途必要。

会話中の手描き舞台に登場する仲間を調べ、最初の舞台を表示する前に、それぞれの共通の立位と歩行画像を背景と並行して読み込む。以降の会話送りで同じ画像を待ち直さないため、人物の移動元を保持したまま進む。失敗や8秒のタイムアウトでは待機を解除する。
