# 3-9 塔の復旧の試作

用語集と地図、3-9 の出発会話・道中の掛け合いを照合。3-3 と同じ塔へ続く古い石組みで、包帯を巻いたフィンは石を持ち上げず通行案内を受け持つ。出発会話と同じ開いた石組みの背景に、四人、石工、管理人、根、石、柵を置く試作を `sprite-lab/storybook/berne-restoration` に作成した。ゲームのセーブや戦闘計算は変更しない。

PC幅の見本で背景と人物・小物の表示、到着状態を部分確認した。根を道具の先が届く位置へ移し、アリアが実際に作業している間だけ薄くなるようにした。中断中は根が残り、再び作業に戻ると続きから取り除かれる。PC幅とスマートフォン幅で根を除く姿勢を部分確認した（`work/restoration-root-after.png`、`work/restoration-root-mobile.png`）。終盤の通路整理時に、石工が石に近づいて持ち上げ、穴まで運び、向きを変えてしゃがむ試作を追加し、その後に暗転を挟んで穴の埋まった昼間の石組みに切り替える。下ろす途中の画面で石工とレオンが重なったため、石を据える間のレオンを離した。調整後のPC幅の画面は `work/restoration-turn-separated.png`。見本にのみ接続し、本編の既定表示は変更していない。

通常と連続手助けの自動シミュレーションでは、完了前に石の設置と暗転が終わることを確認した。ただし任意の速度での完了や、会話画面へ移る本編で演出が継続することは未確認。

フィンは通行案内の掛け合いが選ばれる地点1〜3・10〜12で、包帯付きの右手を使わず左手で案内する既存姿勢を使用する。移動中も包帯付きの歩行姿勢を使う。PC幅で柵との重なりを見つけ、柵の通路側にずらした後の配置を確認した（`work/restoration-guiding-clear.png`）。

溝の照合時、石工が石の脇まで歩いてしゃがみ、レオンが三本溝の図面を持つ姿勢を追加。石の上に立っていたレオンを離した。二人が確認位置へ到着してから図面を表示し、石工が後の設置動作へ移る際の位置も連続させた。PC幅の画面は `work/restoration-inspect-after.png`。

石を持ち上げる間に足踏みしていた点を直し、低い姿勢から立ち上がる4姿勢を追加。石を下ろすときは逆順に使い、姿勢ごとに同じ縮尺・足元を維持する。PC幅の途中状態を `work/restoration-lift-mid-20261028.png`、`work/restoration-lower-mid-20261028.png` で確認した。新たな歩行素材の候補は足の交代が不十分なため不採用。石の表裏切り替えでは画像を縦に潰す代わりに厚みのある側面素材を挟み、面の不透明度を交差させる。PC幅とスマホ幅で回転中の一時停止を確認した（`work/restoration-solid-turn.png`、`work/restoration-solid-turn-mobile.png`）。側面の原画と生成条件は `docs/art-generation/storybook-stone-side-20261028.json`。設置中の手元と回転の自然さは一連の再生で引き続き確認が必要。

試作画面に本編と同じ道中の掛け合いを追加。通常再生では根を除いた後に「根をよければ」が表示されていたため、試作では現在表示中の台詞を描画へ渡し、根の作業をその台詞から始める。フィンの案内も表示中の案内の掛け合いに合わせる。PC幅で通常再生し、根の台詞が出た時のアリアの作業姿勢と、その後に根が消える状態を確認した（`work/restoration-dialogue-root-start-20261028.png`、`work/restoration-dialogue-root-after-20261028.png`）。スマホ幅390×844でも台詞と作業姿勢を確認した（`work/restoration-dialogue-root-mobile-20261028.png`）。台詞が表示されるまで根が残り、途中で地点が変わっても作業を続けることは単体検査で確認。途中開始時・高速進行・スマホ幅の一連の表示、フィンが話す瞬間の到着タイミング、本編の掛け合いからの連携は未確認。

終盤からの試作では根の台詞中に石の設置が始まらないようにし、次の台詞へ移った後に作業が始まることをPC幅で部分確認した（`work/restoration-late-dialogue-wait.png`、`work/restoration-late-dialogue-follow.png`）。ただし連続手助けを50ms間隔で模擬すると、根の台詞は13.8秒・地点13で出て、17.05秒でクエストが完了する。会話を待たないゲーム進行と設置演出の両立、帰還会話を開く境界はまだ解決していない（`work/restoration-assist-dialogue-audit.mjs`）。

試作では掛け合いを順に保持し、根の台詞と作業が終わるまで石の設置を始めない。クエスト完了後も描画用に直前の状態だけを保持し、復旧の表示が終わると実際の完了状態へ戻す。ゲーム状態の完了時刻やセーブ内容は変更しない。50ms間隔の手助けを試作の実画面で実行し、PC幅・スマホ幅で「到着しました」と表示された後も掛け合いと未設置の石が残り、設置後に舞台が完了状態へ切り替わることを確認した（`work/restoration-rapid-arrived.png` / `work/restoration-rapid-finished.png`、`work/restoration-rapid-arrived-mobile.png` / `work/restoration-rapid-finished-mobile.png`）。完了後の一時停止中は画面が変わらず、再開後に演出が終わることもPC幅で確認。連続手助けは試作の一時データ専用で、一時停止・描画準備中・非表示時は進めない。

本編では帰還会話がゲームの完了直後に自動表示され、その間は冒険の描画が止まる。試作での継続だけではこの境界を解決できないため、帰還会話への受け渡し、再訪・画面切り替え時の扱いは本編へ接続する前に検証する。

本編と同じ画面構成を使う一時データの見本 `sprite-lab/storybook/restoration-phone` で、完了後に描画を保持し、石の設置が終わってから本来のクエストクリア画面を開く接続を試作した。クエストの完了状態は先に確定し、描画中だけ前回のパーティ状態を使う。連続手助けの後、PC幅で帰還ダイアログが開くまでと、その背後に修復後の塔が残ることを確認した（`work/restoration-phone-handoff-keep-bg.png`）。スマホ幅では「演出をスキップ」からダイアログを開く操作を確認（`work/restoration-phone-skip-mobile.png`）。完了済みとして開き直した場合は待機せずダイアログを表示。選択中のタブ・別の画面・読み込み不可の場合も待機しない設計とし、状態の分岐を単体検査した。実機・本番の保存データでは試していない。

石を据えた後、石工が立ち上がって石組みから少し下がる動きを追加し、その完了まで帰還ダイアログを待つようにした。PC幅の試作で据え付け後の立ち姿と、本編と同じ画面構成の一時データで連続手助け後のクリア画面を確認した（`work/restoration-phone-retreat-finished.png`）。画像を意図的に404にするローカルの検証用プロキシでも、読み込み失敗の案内が表示され、クエスト完了後にクリア画面へ進むことを確認した（`work/restoration-phone-asset-failure.png`）。

390×844 CSS px の一時データでも連続手助け後にクリア画面から帰還会話の冒頭へ進むことを確認した（`work/restoration-phone-return-mobile.png`）。据え付けから立ち上がりまでの各瞬間はこの確認では撮れていない。運搬の反対足を前にする単独姿勢を2回生成したが、どちらも既存と同じ脚が前に残ったため採用しない。

この接続は `PhoneFrame` の検証用指定でのみ有効で、通常の本編では無効。実際の画面切り替え、非表示・再表示、減速設定、スマホ幅での立ち上がりから帰還までの通しの動きと石工の足運びを確認してから通常表示へ展開する。

石工の運搬歩行は、レオンの歩行を脚の参照にした `mason-carry-stone-v2` を試作へ接続。後ろ足を上げる・足を揃える・前足を上げる姿勢を作り、4コマの頭・足元・身長を立ち上がり姿勢へ揃えた。PC幅と390×844 CSS pxで持ち上げから設置までを連続撮影し、石が手元の近くにあることと、足姿勢の変化を部分確認した（`work/mason-carry-v2-contact.png`、`work/mason-carry-mobile-v2-contact.png`）。画像の生成条件と原本は `docs/art-generation/storybook-mason-placement-20261028.json`。小表示の連続画像だけでは足の接地と左右の交替を正確に判定できず、自然な歩行と断定しない。

未完了：石工の各ポーズと石の接触、フィンの案内と実際の掛け合い表示の同期が未確認。石工の足運びの交替と地面への接地を引き続き確認する。石の側面はクロスフェードの暫定表現であり、自然な回転と下ろす時の手の接触は再確認が必要。動作と台詞、高速進行・途中状態のつながりを実装し、PC幅・スマートフォン幅の一連の実画面と帰還会話への切り替えを検証してから本編へ接続する。スマートフォン実機は未確認。

縦長の本編構成を再確認したところ、従来の横長背景は上下に大きな境界があり、人物が小さかった。塔と石組みを参照して穴のある縦長背景と設置後の背景を生成し、穴を基準に人物・石・柵を同じ倍率で配置した。ミラが柵に重ならないよう位置を調整し、画面奥の管理人が背景の後ろに隠れる描画順も修正した。PC幅では舞台を縮めず、会話履歴の表示を二行にして足元を見せる。履歴自体はスクロールできる。画像の原本・生成指示・ハッシュは `docs/art-generation/storybook-restoration-portrait-20261028.json`。

PC幅の石工の接近、持ち上げ、運搬、設置、退避は `work/restoration-sequence-pc/` の連続画像で確認した。390×844の本編構成でも連続手助け中の設置から退避までを確認し、石の着地点を穴の下端に合わせ直した。石が横向きに見えたため、縦長背景では設置時に石組みの向きへ回す（`work/restoration-portrait-turn/`）。設置後のクリア画面から帰還会話へ進むことも確認した。手と石は近接するが、足の滑りや回転途中の自然さは小さな表示からは断定できない。フィンの案内が話し始めた瞬間から姿勢に反映されるかもまだ必要。本編の既定表示への接続は未実施。

フィンが案内の台詞に合わせて移動し始めると、話し始めに案内姿勢を取れないため、最初から案内位置に立ち、台詞に合わせて姿勢を切り替える。PC・縦長の両配置で、初めの台詞に切り替わる際に位置が変わらず案内姿勢を取ることを単体検査した。また、塔の試作では景色の読み込み中に会話を進めず、表示も隠す。画像の応答を8秒遅らせた本編構成の一時データで、読み込み中に会話が表示されず、準備後に最初の掛け合いが表示されることを確認した。読み込み中もゲーム自体は進行するため、長時間の読み込みや他の場面への適用は別途検証が必要。

運搬の最後は、上げていた足を地面に戻して少し止まってから石を下ろすようにした。PC幅の連続画面を拡大し、接地から石を下ろすまでの変化を確認した（`work/restoration-landing-check/landing.png`）。390×844 CSS pxの連続手助けでも設置と退避を確認した（`work/restoration-landing-mobile/montage.png`）。石の表裏は引き続き側面画像を介した切り替えで、実機での見え方は未確認。

3-9の本編冒険中にもこの描画と完了時の受け渡しを有効化した。`restoration-phone` の一時データからも専用指定を外し、本編と同じクエスト選択で演出に入るようにした。PC幅とスマホ幅で連続手助け後にクリア画面から帰還会話へ進むことを確認。描画中断、再訪、失敗時の分岐と通常・高速進行、モーション軽減の組み合わせは単体検査済み。実際のユーザーのセーブデータやスマートフォン実機では確認していない。上記の過去記録にある「本編未接続」は当時の状態を示す。
