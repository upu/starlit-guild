# 4-2 村はずれへの道：冒険表示の現状

用語集の4-2は `lantern-detour`。四人が荷運び人を村はずれへ案内し、灯籠を調べて道の草を刈る。出発・帰還会話は `hill-path-v1` の村道で、帰還後に灯籠の手入れを村の人へ引き継ぐ。

一時データの `/sprite-lab/storybook/lantern-road` を追加し、PC幅で現状を連続再生した（`work/lantern-road-baseline/00.jpg`〜`44.jpg`）。現状は汎用の道標や小さな灯籠アイコンが作業ごとに現れ、荷運び人が見えない。背景も固定された既存の交易路で、進路や灯籠との位置関係が読み取りにくい。専用の絵本調表示は未実装で、スマートフォン幅の検証も必要。

次は会話の村道とつながる背景・荷運び人・灯籠を同じ地面に配置し、案内、点検、草刈りの動作と移動を実際の工程に合わせて検証する。セーブや進行計算は変えない。

会話背景を参考に、広い道を持つ横長・縦長の冒険用背景を生成した。既存の荷運び人、煤けた灯籠、草、四人の姿勢を重ねた静止の仮配置をブラウザーで確認し、灯籠を道端へ寄せ、草と荷運び人の足が重ならないようにした（`work/lantern-layout-qa.jpg`）。配置の座標と縮尺は `lib/road-lantern-layout.ts`、人物と灯籠の表示範囲は `tests/road-lantern-layout.test.mjs`。画像の生成情報は `docs/art-generation/storybook-lantern-road-20261028.json`。

試作 `/sprite-lab/storybook/lantern-road` と縦長用 `/sprite-lab/storybook/lantern-road-portrait` では、新しい背景と荷運び人、同じ場所に残る灯籠・草を冒険の描画へ接続した。案内の開始時に荷運び人と四人が進み、灯籠の点検ではレオン、草刈りではアリアが近づく。仲間を横切って重なりすぎた箇所に中継点を置き、灯籠の点検位置を手の高さに合わせた。草刈りは既存の二姿勢を交互に表示する。移動中や戦闘中、行動できない人物は作業姿勢を取らない。通常速度の一時データをPC幅 `work/lantern-trial-pc-route/`、縦長 `work/lantern-trial-mobile-route/` と `work/lantern-mobile-inspect-fixed/` で部分再生し、点検・草刈りを確認。ゲーム状態を変えず、両幅で人物が作業位置へ到着することは `tests/road-lantern-road.test.mjs` でも検査する。

描画専用の工程待ちを設け、高速進行でも作業位置への移動と作業姿勢を見せてから次へ進む。ゲーム上の完了後も見本では直前の状態を描画に保持し、最後の草刈りからアリアが仲間へ戻るまで「到着しました」を待つ。PC幅 `work/lantern-queue-return-pc/` と縦長 `work/lantern-queue-return-mobile/` の連続記録で終盤の工程と帰着を確認。自動検査では両幅で15工程の順序と作業、行動不能時の待ち解除、セーブ不変を確認した。

同じ場所への不自然な往復を減らすため、レオンとアリアは最初に作業場所へ着いた後、別の工程の間もそこに残るようにした。アリアの足が背景の茂みと重なったため、草を通路寄りへ移し、ミラとの間隔も広げた。繰り返しの工程はその場で動作を切り替え、後半の表示を短くした。PC幅 `work/lantern-retained-rapid-pc/` と縦長 `work/lantern-retained-rapid-mobile/` で高速再生の最初から到着までを連続確認。自動検査では作業位置の維持と、ゲーム完了後20秒未満で表示が終わることを両幅で確認した。

本編の既定表示に登録し、作業の描画が終わるまでクリア画面を待つようにした。ユーザーのセーブを変更しない一時データを本編と同じ `PhoneFrame` に渡し、PC幅と390×844の縦長ブラウザーで、作業終了からクリア画面、帰還会話「煤の向こう」への遷移を確認した。演出をスキップしてクリア画面へ進むことも一時データで確認している。描画用の待機はゲームの完了・報酬を変更しない。

戦闘や休止からの復帰、向き・画角変更の実画面確認、スマートフォン実機での確認は引き続き必要。帰還会話では村道と灯籠が共通する一方、冒険画面とは人物と背景の配置が完全には一致しない。
