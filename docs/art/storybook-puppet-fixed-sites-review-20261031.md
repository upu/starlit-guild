## 敵名が対象から離れる原因と修正

2-7のスマホ幅で、操り手の名前と掛け声は端で欠けてはいなかったが、頭よりかなり上へ離れていた。描画に使うセル全体が身体の回避範囲になり、ゴーレムの透明な余白にも文字を置けず、長い一行の名前がさらに上へ追い出されていた。

`roadLabelBody` は手描きの人形・ゴーレム・覆面の少女について、通常・歩行・行動の0〜7コマの可視画素を覆う範囲を使う。左右の余白は反転しても同じ範囲で覆う。比較表示や他種の敵は元の範囲を維持する。`roadLabelWrapWidth` は画面端からの距離にも合わせて折り返し、端を避けるためだけに名前を遠くへ動かさない。配置の安定化、人物・荷物・HP表示を避ける処理は維持した。

`tests/road-label-body.test.mjs` で原画の各8コマと両向きの可視画素が範囲内へ収まること、ゴーレム・台・長い名前が並ぶスマホ幅で名前が対象の近くへ置かれること、比較表示の互換を検査する。`RoadJourneyCart.paint` へ渡す外観も直前フレームの値から現在の `look` へ揃え、最初のフレームから同じ描画順を選ぶ。

## 一時データ見本の終了・休息時の手助け

低い休息姿勢を確認するため、共通の `ChapterFourPhoneStudy` に任意の `level` を追加した。2-7の `blockade-phone` はLv18、他の既定値はLv40のまま。短いクエストの「帰着の手前から」が13区間目へ到達しようとして完了後まで進んでいたため、最終区間より先へ進まない開始位置にした。

実画面で連続手助けを使った際、完了直後の余分な一回と、全員が休息中なのに攻撃を送る場合に、それぞれゲーム側の正当な拒否が見本の例外になっていた。現在の一時データに実行中の冒険がある場合だけ手助けを送り、休息中は回復、それ以外は攻撃へ切り替える。ゲーム側の拒否条件は弱めない。

`tests/storybook-phone-trial.test.mjs` は進行・手助け・描画の停止と再開に加え、完了後でeffectの解除前に届く手助け、全員が休息へ入った直後の回復、2-5・2-6・2-7の最終区間を保持する開始位置を、実際の状態更新で検査する。

## 実画面の範囲

PC1280×900、ブラウザーのスマホ幅390×844 CSS pxで確認した。約350msごとの画像と時間一覧・表示テキストは `work/fixed-sites-review-20261031/`。区間間は見本の操作で停止した。抜粋と原寸画像を目視しており、全フレーム動画やスマホ実機の検査ではない。

- 2-6のLv40は両幅の `golem-*-a`。小型・大型・大小の三戦、固定荷物、敵の大きさと足先、完了カード、`golem-*-return` の帰還会話1/18までを記録。これも敵名修正前の工程記録。
- 2-7のLv40は両幅の `blockade-*-a/b` と帰還会話1/32。名前修正後は `blockade-*-labels` の約40秒を両幅で撮り直した。三戦、退場と登場、台上の品物、操り糸、止まった人形の引き寄せ、完了までを再生し、`blockade-*-labels-contact.png` と原寸で確認。スマホ幅の長い名前は二行になり、頭の近くと画面内に収まっている。
